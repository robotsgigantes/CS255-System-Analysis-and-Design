# CS255-System-Analysis-and-Design
The client for this project, DriverPass, wanted us to design a system that would allow customers to study materials, schedule behind the wheel training, and schedule exams in an effort to aid the customers to pass their driving test and become licensed. The foundation of the project is based in the low percentage of successful attempts at the DMV for attaining a vehicle license.

I feel like my approach to separating out the client's needs and organizing them into diagrams was my strongest suit throughout this class and project. Being able to analyze and convey a client's wants for a system is the first step to designing the system, and probably the most important.

If I could redo one part of this project it would probably be the system design document. It felt kind of rushed and lackluster compared to the business requirements documentation. In revising it, I would probably just end up rewriting it to make it more cohesive in general, but also more streamlined for non-technical audiences.

It is extremely important to consider the user's needs when designing a system due to the fact that the user is the one using it. A poorly designed, non-user friendly system or program leads to many unhappy users who will either not return or advise their peers against using it. DriverPass wanted to retain a client base, and grow, and you can't grow if your system is not intuitive. Updating the website with current information and news is one way to retain a user base and that is one of the non-functional requirements that DriverPass wanted.

When designing software, my approach is to break the program down into various methods, objects, and functions to make designing easier by making the components smaller to work with. This can be applicable to system design due to the nature of a system being like written code. Together it works, but they both have smaller parts that need to be able to work independently.
